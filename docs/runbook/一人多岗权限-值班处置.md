# 一人多岗权限 — 值班处置（rbac-1）

> 适用：菜单看不到/点不动、身兼多岗、给同事加岗/下岗、停用岗位、查谁越权点了功能。
> 一句话：**一个人可以有多个岗位，能干的事是各岗位加起来（并集，不是交集）；岗位一停，下次操作立刻失效，不用对方重登。**

## 一、速查（贴工位）

- 登录后系统按你的**全部在岗岗位**自动拼菜单：两岗共有的菜单只显示一次，两岗各自的都显示。
- 页面能看到菜单、按钮却提示 **403 无权限**：说明该功能不在你的岗位范围内，找管理员加岗，不要反复点。
- **401** = 没登录/登录过期 → 重新登录；**403** = 登录了但岗位不够 → 找管理员，重试没用。
- 加岗、下岗、停岗、恢复**都不用对方退出登录**：他手上的令牌还在，**下一次点按钮就按新岗位生效**。
- 普通同事只管干活；角色、菜单、授权只有 **ADMIN（系统管理员，王芳 venue_admin）** 能维护。
- 初始密码均为 `Venue@2026`，首次登录请立即改密。

## 二、场务最常见的 5 种情况

### 1. "我怎么没有某某菜单 / 按钮灰的"

1. 先确认登的是自己的工号：`GET /api/auth/me`，看 `roles` 里有哪些岗位。
2. 再拉一次自己的菜单：`GET /api/auth/menus`——菜单是实时按岗位拼的，刚加完岗刷新页面就有。
3. 确实该有却没有 → 是没给这个岗位授权，找 ADMIN 在「权限管理」里给岗位勾菜单，不是你账号坏了。

### 2. 同事身兼两岗 / 调岗了，要加岗或下岗（ADMIN 操作）

```bash
ADMIN=<王芳的 accessToken>
# 查人（按工号/姓名关键字）
curl "http://localhost:8080/api/admin/rbac/users?keyword=陈晨" \
  -H "Authorization: Bearer $ADMIN"

# 覆盖式授岗：提交后该同事的岗位 = 提交的全集（售票岗 3 + 检票岗 4）
curl -X PUT http://localhost:8080/api/admin/rbac/users/<用户id>/roles \
  -H "Authorization: Bearer $ADMIN" -H 'Content-Type: application/json' \
  -d '{"roleIds":[3,4]}'

# 一键下岗（离职/借调结束）：传空数组，他下次任何操作立即 403
curl -X PUT http://localhost:8080/api/admin/rbac/users/<用户id>/roles \
  -H "Authorization: Bearer $ADMIN" -H 'Content-Type: application/json' \
  -d '{"roleIds":[]}'
```

> 注意是**覆盖**不是追加：要加一岗，把原有岗位和新岗位一起提交；漏提一个等于撤掉那个岗。

### 3. 紧急收权：整个岗位先停掉（ADMIN 操作）

出事故/审计要求时，不用逐人下岗，直接停岗位——所有挂这个岗的人**下一次点击统一收口**，
他们的另一个岗位不受影响：

```bash
# 停用售票岗（id 先从角色列表查）
curl -X POST http://localhost:8080/api/admin/rbac/roles/<角色id>/disable \
  -H "Authorization: Bearer $ADMIN"
# 恢复
curl -X POST http://localhost:8080/api/admin/rbac/roles/<角色id>/enable \
  -H "Authorization: Bearer $ADMIN"
```

- 停用后当事人菜单里该岗位那一支立刻消失，再点相关功能返回 403；
- ADMIN 内置角色**不能停用也不能删除**（系统自锁保护），如要收管理员权限请联系运维走流程。

### 4. 人离职/账号异常：直接停用账号，对方立刻掉线（ADMIN 操作）

停岗位是"收走某一类权限"，**停用账号**是"这个人整个不许进系统"。离职、账号疑似外泄时用这个：

```bash
# 先按工号查用户 id
curl "http://localhost:8080/api/admin/rbac/users?keyword=周洋" \
  -H "Authorization: Bearer $ADMIN"
# 停用（id 用上一步查到的）
curl -X POST http://localhost:8080/api/admin/rbac/users/<用户id>/disable \
  -H "Authorization: Bearer $ADMIN"
# 事情查清后恢复可登录
curl -X POST http://localhost:8080/api/admin/rbac/users/<用户id>/enable \
  -H "Authorization: Bearer $ADMIN"
```

停用生效的范围（不用等令牌过期，**下一秒**全部生效）：

- 对方手里现有的登录态（访问令牌）下一次操作即 **401 掉线**；
- 所有设备上的刷新令牌全部作废，无法再自动续登；
- 即使密码正确，停用期间也**登录不进来**（提示"账号已停用"）；
- 日后重新启用，停用前的旧登录态**不会复活**，必须重新输入密码登录；
- 不能停用**当前正在登录的自己**（防自锁，系统会拦）；非 ADMIN 调用返回 403。

### 5. 查"谁在乱点没权限的功能"（越权审计，ADMIN 操作）

每次岗位不够的访问都会被**统一拦下并自动记一笔**（谁、工号、当时有哪些岗、点的什么功能、
需要什么权限、IP、时间），不会放过去也不用场务登记：

```bash
# 按工号查
curl "http://localhost:8080/api/admin/rbac/deny-logs?username=box_office01&size=20" \
  -H "Authorization: Bearer $ADMIN"
# 按路径/时间圈
curl "http://localhost:8080/api/admin/rbac/deny-logs?path=/mask&from=2026-09-24T00:00:00" \
  -H "Authorization: Bearer $ADMIN"
```

偶发 403 多为误点；**同一工号短时间大量 deny 记录**（尤其集中在权限管理/导出）先核实本人操作，
再按信息安全事件上报。

## 三、菜单与权限是怎么对上的（给想搞懂的人）

- 菜单树分三层：**目录 → 菜单（页面）→ 按钮（具体动作）**。每个按钮挂一个权限码，
  如 `ticket:order:create`（下单）、`ticket:ticket:check`（检票入场）。
- 一个岗位 = 勾选的一批菜单/按钮；一个人多个岗位时，权限码**取并集**：
  陈晨有售票岗（能下单）+ 检票岗（能检票），所以两件事都能做；
  但建座位只授给了前台通岗，她两个岗都没有，就是 403——**并集是相加，不是要求两岗同时满足**。
- 给岗位加/减功能在「权限管理 → 角色 → 勾选菜单」（`PUT /api/admin/rbac/roles/{id}/menus`），
  同样是覆盖式，保存后该岗位所有人下一次操作即变化。

## 四、绝对不要做

1. **不要直接改数据库** `t_admin_user_role` / `t_rbac_role_menu` 绕过审批——操作界面有校验（防删内置、防删父节点），直改库可能锁死所有人。
2. 不要停用或删除 `ADMIN` 角色、不要给最后一个管理员下岗（界面会拦，别想办法绕）。
3. 不要把岗位建成交叉依赖（"必须同时有 A 和 B 才能做"）——本系统多岗就是并集放行，没有"交集才放行"的岗位。
4. 403 不是系统故障，**不要重启服务试试**；先查岗位授权。重启不会改变任何权限。
