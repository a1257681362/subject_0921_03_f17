# 检票备注敏感词扫描 — 值班处置（sensitive-1）

> 适用：检票/退票/作废/取消排期备注的敏感词拦截与打码异常、词库维护、命中留痕核查、
> **一出异常立即切回旧逻辑的回退预案**。

## 一、速查

- 口径：自由文本（检票备注 `reason`、取消排期 `cancelReason`）入系统前过 DFA 敏感词扫描；
  **高危（HIGH）命中直接拦截本次操作**（票/排期状态不动），**低危（LOW）命中片段打码（`*`）后放行**。
- 每次命中留痕 `t_sensitive_hit_log`：被扫原文、命中词与级别、原文片段、**码点起止位置**、
  处置（BLOCKED/MASKED）、操作人、请求号。高危拦截的留痕走独立事务，业务回滚也保得住。
- 归一：全角→半角（NFKC）、大小写折叠、跳过空白/零宽字符/插缝符（`· . * ~ - _`），
  「黄 牛」「黄·牛」「加Ｖ」都按「黄牛」「加v」匹配；命中位置仍映射回**原文**码点区间。
- 词库 `t_sensitive_word` 分 HIGH/LOW 两级；管理端改词后**立即热刷新** DFA，无需重启。
- 代理平台入站报文默认**豁免**扫描（非人工输入）；现场人工入口全扫。

## 二、回退预案（一出异常立即切回旧逻辑）

三级预案，从重到轻；**现场检票绝不能被扫描故障挡住**。

### 1. 扫描故障自动放行（默认开启，无需操作）

`evops.sensitive.fail-open=true`（默认）：扫描引擎/留痕链路自身抛异常时，本次请求记 ERROR
日志后**按原文放行**，检票照常。日志关键字：`敏感词扫描异常，本次按原文放行`。

> 演练/强卡场景可置 `EVOPS_SENSITIVE_FAIL_OPEN=false`：扫描不可用时直接拦截并提示
> 「敏感词扫描暂不可用，请稍后重试或联系管理员切回旧逻辑」。

### 2. 总开关切回旧逻辑（应急首选）

```bash
# 重启前加环境变量（或改 application.yml 的 evops.sensitive.enabled: false）
export EVOPS_SENSITIVE_ENABLED=false
```

关闭后：所有文本**完全不扫描、不打码、不留痕**，行为与上线前旧逻辑完全一致。
恢复：置回 `true` 重启即可，期间未扫描的历史数据可在留痕表按时间窗排查补审。

### 3. 词库误伤收窄（个别词误拦，不动开关）

某词误拦正常业务时，ADMIN 停用该词即可（留档不删除，立即生效）：

```bash
# 先查词 id
curl "http://localhost:8080/api/ticket/sensitive/words?keyword=误伤词" \
  -H "Authorization: Bearer <adminToken>"
# 停用
curl -X POST "http://localhost:8080/api/ticket/sensitive/words/<id>/disable" \
  -H "Authorization: Bearer <adminToken>"
```

恢复：`POST /api/ticket/sensitive/words/<id>/enable`。词库被改乱时可整库重刷：
`POST /api/ticket/sensitive/reload`（返回当前生效词数）。

## 三、常见情况

### 1. 场务反馈「正常备注被拦」

1. 让 ADMIN 查留痕确认命中了哪个词、什么位置：
   ```bash
   curl "http://localhost:8080/api/ticket/sensitive/hits?scene=CHECK&action=BLOCKED" \
     -H "Authorization: Bearer <adminToken>"
   ```
   每条含 `word`（词库词）、`matchedText`（原文片段）、`startCp/endCp`（码点位置）、
   `originalText`（完整原文）。
2. 确属误伤：按「预案 3」停用该词或降为 LOW（停用 HIGH 词后按 LOW 重录一条）。
3. 观众用全角/插缝变体绕过属**正常拦截**，向场务说明口径即可。

### 2. 低危词打码后业务方要看原文

流水/单据里落的是打码文本（如「请\*\*信领票」），原文在留痕表：
按 `bizRef`（票号/预约号）查 `GET /api/ticket/sensitive/hits?keyword=<票号>`，
`originalText` 即完整原文（仅 ADMIN 可见）。

### 3. 新词上线前先试扫（避免误伤）

```bash
curl -X POST http://localhost:8080/api/ticket/sensitive/preview \
  -H "Authorization: Bearer <adminToken>" -H 'Content-Type: application/json' \
  -d '{"text":"加 微 领票"}'
```

返回命中词/级别/原文片段/码点位置，不落业务不留痕。确认无误后再 `POST /words` 入库。

### 4. 新增/调整词库

```bash
curl -X POST http://localhost:8080/api/ticket/sensitive/words \
  -H "Authorization: Bearer <adminToken>" -H 'Content-Type: application/json' \
  -d '{"word":"新词","level":"HIGH","category":"FRAUD","remark":"来源说明"}'
```

- 级别仅 `HIGH`/`LOW`；分类建议 FRAUD/PORN/GAMBLING/SCALPER/ILLEGAL/AD。
- 入库自动归一；与库内已有词**同形**（全角/插缝变体）会被拒绝，改级别请停用旧词重录。
- 生效词数变化看日志 `敏感词 DFA 已（重新）装载` 或调 `/reload` 确认。

### 5. 平台入站报文也要扫描（默认豁免）

确认平台侧文本确需管控时：`EVOPS_SENSITIVE_SCAN_AGENT=true` 重启。
注意：误拦会导致平台同步失败进异常清单，开启后盯 `t_agent_parse_error`。

## 四、配置速查（`evops.sensitive`）

| 配置 | 默认值 | 说明 |
|---|---|---|
| `enabled` / `EVOPS_SENSITIVE_ENABLED` | true | 总开关，false 完全切回旧逻辑 |
| `fail-open` / `EVOPS_SENSITIVE_FAIL_OPEN` | true | 扫描故障按原文放行（不挡检票） |
| `scan-agent-inbound` / `EVOPS_SENSITIVE_SCAN_AGENT` | false | 平台入站报文是否扫描 |
| `mask-char` | `*` | 低危命中的打码字符（取首码点） |
