# 检票数据脱敏 — 值班处置（mask-1）

> 适用：检票预约单据接口/导出脱敏异常、白名单角色调整、脱敏规则应急收口/恢复、明文查看留痕核查。

## 一、速查

- 打码口径：观众姓名保留首字（周洋→周\*），11 位手机号保留前 3 后 4（138\*\*\*\*8000）。
- 默认白名单角色：`STAGE_STAFF`（场务）、`ADMIN`（管理员）。售票/检票岗 `STAFF` 只见打码值。
- 规则只增不改：发布新版本后旧版置 SUPERSEDED 留档，**不要也不能**直接改库内历史行。
- 任何「明明是白名单却看到打码」「规则疑似没生效」先看日志关键字：`脱敏规则`、`敏感字段明文查看留痕写库失败`。

## 二、常见情况

### 1. 场务反馈看不到观众完整姓名/电话

1. 确认登录工号与角色：`GET /api/auth/me`，看 `role` 是否 `STAGE_STAFF`/`ADMIN`。
2. 角色取**库内最新值**（令牌校验时实时回填），改角色后无需用户重新登录即生效；若刚调整，让用户刷新重试。
3. 查当前生效规则白名单：`GET /api/ticket/mask/rules/current`（需 ADMIN），确认该角色在 `whitelistRoles` 内。
4. 若规则缺失/读库异常，系统**安全失败关闭**（全员打码）并打 ERROR：`脱敏规则无 ACTIVE 版本` 或 `加载脱敏生效规则失败`。此时让 ADMIN 发布一条有效规则版本恢复，不要手工删表。

### 2. 应急收口（临时全员打码，含场务）

ADMIN 调发布接口，白名单传空数组：

```bash
curl -X POST http://localhost:8080/api/ticket/mask/rules/publish \
  -H "Authorization: Bearer <adminToken>" -H 'Content-Type: application/json' \
  -d '{"fieldRules":[{"field":"visitorName","maskType":"NAME"},
                     {"field":"contact","maskType":"CONTACT"}],
       "whitelistRoles":[],"remark":"应急收口：全员打码"}'
```

发布即生效（无需重启），旧版本自动 SUPERSEDED 留档。**恢复**时再发一版，`whitelistRoles` 放回 `["STAGE_STAFF","ADMIN"]`。

### 3. 谁在什么时间看了明文（审计核查）

```bash
# 按工号 + 出口通道（API 接口 / EXPORT 导出）
curl "http://localhost:8080/api/ticket/mask/view-logs?username=stage01&channel=EXPORT" \
  -H "Authorization: Bearer <adminToken>"
# 按某条预约单据回查
curl "http://localhost:8080/api/ticket/mask/view-logs?bizType=CheckinAppointment&bizId=<预约号>" \
  -H "Authorization: Bearer <adminToken>"
```

每条留痕含：工号/角色/业务单据类型与预约号/字段名/打码类型/命中的规则版本/出口/请求路径/请求号/查看时间。
留痕写库失败不阻断业务，但会打 ERROR `敏感字段明文查看留痕写库失败`——出现即需 DBA 核查 `t_sensitive_view_log`，不可忽略。

### 4. 导出预约单据

```bash
curl -OJ "http://localhost:8080/api/ticket/checkin/appointments/export?status=ACTIVE" \
  -H "Authorization: Bearer <token>"
```

- CSV 为 UTF-8 带 BOM，Excel 直开中文不乱码；敏感列按当前角色脱敏，与页面/接口同一口径。
- 单次上限 5000 行（`EVOPS_MASK_EXPORT_MAX` 只能调小）；超限在生成文件前直接回 JSON 提示，按时间/座位/状态缩小范围分批导出，**不会**得到半截 CSV。

### 5. 非 ADMIN 调用规则/留痕接口返回 403

预期行为：规则发布、版本查询、留痕查询仅 ADMIN。需要开放给某岗位走审批后用 ADMIN 账号操作，不要在代码里放宽。

## 三、数据与表（Flyway V5）

- `t_mask_rule_version`：规则版本（全表仅一行 ACTIVE；SUPERSEDED 留档）。
- `t_sensitive_view_log`：明文查看留痕，只追加，不提供修改/删除入口。
